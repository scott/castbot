# S07b approval cards

A web turn that asks for a tool shows one approval card in the chat. The card names the tool, the time in the user's zone, and the arguments with secret values replaced by Hidden. Approve and Deny are the only actions. Deny is the only danger button. A second click, or a click from another tab, changes nothing: one permission response and one audit row. A card that the agent no longer has pending becomes inactive and says the request is no longer active.

The server owns the wait. The default is 10 minutes, and `CASTBOT_APPROVAL_TIMEOUT` can set it (at least 1 second, at most 24 hours). When the wait ends, the server posts a denial, marks the card expired, and writes an audit row for `system:timeout`. Closing the browser stream does not deny the card. The same card is there after a reconnect. A paused machine is woken on the click, then the decision is posted. An expiry or a restart denial does not wake a paused machine, and a denial that keeps failing waits longer between tries (2 seconds, then 4, 8, 16, 32, capped at 60) with its own 15 second deadline. Schema version 13 adds `approvals` and `audit_log`. Version 12 stays the real runtime migration.

The click checks the run id before it claims the row. Claim, the permission response, and the audit row run on a server context, so a tab that closes mid-click still lands the decision when the agent accepts it. If that post fails, the claim returns to pending and a later click or the timeout can try again. On startup, and every second after a 30 second grace, a row that was claimed and not confirmed is posted again and then audited. A lost request is marked inactive and does not write `approval.approved`. A claim whose run has already failed is denied if the guest is still waiting, then marked inactive, and it does not write `approval.approved`. The one second loop still marks rows due while a post is in flight, and each sweep posts one denial and one recovery.

A bundle publish or a secret change does not restart the guest while a web approval is pending, while another run is still open, or while this run has already started (`waiting_approval`, or a stream offset above 0). The restart waits until that run finishes. The next message applies it before the new turn, because a brand new run with offset 0 is left out of the check. Opening the agent page or saving the agent waits the same way while any run is streaming or waiting. A wait is logged only when a bundle or a secret change is actually pending, once per change of that wait, with its reason and an 8 character prefix of the old and new secret fingerprint. The 15 minute bound starts at that first wait, not at the run's start. A pending web approval is never forced; its own timeout ends that wait. After the approval is gone, a wait that has already passed 15 minutes proceeds, and that forced restart is logged once.

A run that was left open at shutdown has its pending cards marked inactive. The expiry loop posts Deny when the machine is still reachable, and it does not wake a paused one. After a decision the run returns to streaming while the tool continues. The waiting bar, the sidebar badge, and the nav count refresh with the card.

Secret names match whole segments, and a name that ends in `_key` is hidden unless it is on a short allow list: `sort_key`, `cache_key`, `object_key`, `partition_key`, `primary_key`, `idempotency_key`, `host_key`, `public_key`, and `ssh_public_key`, including camelCase. `auth`, `pass`, `jwt`, `pat`, `bearer`, `basic_auth`, and `auth_header` are hidden. Token counts stay visible (`tokens`, `num_tokens`, `token_count`, `max_tokens`). `max_secret` and `secret_count` do not. Ordinary names such as `session`, `tokenizer`, and `secretary` stay visible. `env` and `headers` stay hidden. A bearer token inside a command string or an array is replaced with `Bearer Hidden` and the rest of the argument stays. Argument text is clipped at 80 runes so a long value stays valid UTF-8.

An approval that arrived from a Cast CLI journal is read only. It has no buttons. The real journal writes the decision before the permission, with an empty session and no tool name. The tool is copied from the matching permission, and the decision is attached to that permission's thread so it does not open a second Cast CLI thread. The thread shows the ask, then the decision. A web turn's own journal (caller `control_plane` on the web thread) is not copied in as a second card. A recovery of a claim whose run has already failed posts Deny when the guest is still waiting and marks the row inactive. It does not post Approve and it does not write `approval.approved`. Before that inactive mark, recovery reads the castlet journal. A decision already stored for that request is audited as approved or denied, so a delivered approval still has its audit row when the prompt is gone. A request the agent no longer has, with no journaled decision, is inactive on that path too. The waiting bar and badges are sent again on the stream event that follows the decision, including the done event, so a click whose card was already swapped still clears them. Another user's card, run, and event stream are 404, and the body does not include the command or the approval id.

## What the tests show

`TestAskApproveFinishesAndDenyEnds` approves one bash ask through to done and denies another with the denial text. The stored arguments and the audit detail do not contain the secret. A bad CSRF token is 403 and posts nothing. `TestApprovalDoubleSubmitOneRespond` sends two clicks at once plus a third and keeps a single approval. `TestApprovalTimeoutPostsDeny` moves a fake clock to the deadline, posts the denial, and shows Expired after reload. `TestClosedStreamDoesNotDeny` drops the stream and still shows the pending card, including after a reconnect. `TestApprovalAuthz` is the two-user table: the other account gets 404 on the card, both decisions, the run id paired with the owner's approval id, the event stream, and the agent page. `TestCLIApprovalIsReadOnly` renders a journal decision with no Approve or Deny, using the real order: a decision with no tool name, then the permission. `TestCLIDecisionPicksUpToolFromLaterPermission` rewrites that decision to name bash and does not copy a `control_plane` permission into the web thread. `TestApprovalTimeUsesUserZone` shows 3:42 PM for America/New_York at 20:42 UTC. `TestPausedMachineWakesBeforeApproval` wakes a paused machine before the permission response. `TestExpiryDoesNotWakePausedMachine` expires a card on a paused machine without a wake. `TestUnknownApprovalGoesInactive` forgets the request and leaves the card inactive. `TestMismatchedRunDoesNotClaim` returns 404 for the wrong run id and leaves the row pending. `TestCanceledClickStillDecides` covers a click whose browser gives up after the agent has the decision, and a click the agent never receives. `TestWebJournalDoesNotDuplicateCard` feeds the web journal shape and keeps a single card. `TestSecretArgNamesStayHidden` keeps the extra secret names off the page, the card, the event stream, the run events, the stored arguments, and the audit. `TestLongValueTruncatesOnRunes` clips on runes. `TestAbandonedApprovalIsDeniedWhenLive` posts Deny after a restart leaves the card inactive. `TestRunLeavesWaitingAfterDecision` returns the run to streaming and refreshes the waiting bar. `TestApprovalSurvivesCutProxy` cuts the stream twice and still approves once. `TestDeferGuestRestartWhileApprovalPending` waits out a reload during a pending card or a started run. `TestDeferGuestRestartBound` uses a fake clock and lets the restart proceed 15 minutes after the first wanted wait, not when the run itself is old. `TestDeferGuestRestartDoesNotForcePendingApproval` keeps a fresh approval pending past that bound. `TestApprovalsMigration` checks schema version 13 and the two tables. `TestScrubJSONDropsSecretKeys` and `TestScrubJSONDropsCamelCaseAndBearer` drop secret keys, camelCase names, and a Bearer value, and keep `max_tokens`. `TestScrubJSONOrdinaryNamesStay` keeps the ordinary names, including public keys and token counts, and drops `env`, `headers`, `auth`, `pass`, other `*_key` names, `jwt`, `pat`, `bearer`, `max_secret`, and `secret_count`. `TestScrubJSONBearerInsideStrings` hides a bearer token inside a command string and inside an array. `TestDecisionStreamCarriesChrome` checks the done event still carries the waiting bar and the nav badge. `TestRecoveryDoesNotApproveAFailedRun` and `TestRecoveryLostRequestStaysInactive` keep a failed run and a lost request off the approved audit. `TestRecoveryJournalKeepsApprovedAudit` writes `approval.approved` when the journal already has that decision and the prompt is gone. `TestGuestRestartDeferralIsLogged` records one deferral and one forced restart, and stays quiet when the fingerprint already matches, without the secret or the full fingerprint.
